# Feature Architecture Plan: JWT Authentication System for Context-Agent

## 1. Overview
This document outlines the architectural plan for adding a multi-user JWT-based Authentication System to the existing Context-Agent. Currently, the system is single-user and runs locally. This feature will introduce user accounts, login/signup flows, and secure API access using JSON Web Tokens (JWT).

## 2. Requirements
- Users must be able to sign up with an email and password.
- Users must be able to log in to receive a JWT access token.
- The FastAPI backend must secure its routes so that only authenticated users can access the `/api/projects` and `/api/files` endpoints.
- The React frontend must have a Login and Signup page.
- The React frontend must store the JWT token locally (e.g., in localStorage) and attach it to the `Authorization` header of all outbound API requests.

## 3. Backend Implementation (FastAPI)

### 3.1 Dependencies
- Add `PyJWT`, `passlib[bcrypt]`, and `python-multipart` to the backend dependencies.

### 3.2 Database Models (`models/user.py`)
- Create a new `User` Pydantic model containing:
  - `id`: str (UUID)
  - `email`: str
  - `hashed_password`: str
- Note: For this MVP, users can be stored in a simple JSON file (e.g., `users.json`) managed by a `UserManager` class, to avoid needing a full SQL database setup.

### 3.3 Auth Routes (`backend/auth_router.py`)
- Create a new FastAPI router with the following endpoints:
  - `POST /api/auth/signup`: Accepts email and password, hashes the password, and saves the user.
  - `POST /api/auth/login`: Accepts email and password, verifies against the hashed password, and returns a JWT token.

### 3.4 Auth Middleware (`core/auth.py`)
- Create a dependency function `get_current_user` that:
  - Extracts the JWT from the `Authorization: Bearer <token>` header.
  - Decodes the token using a secret key.
  - Returns the authenticated user ID.
- Apply this dependency to the protected endpoints in `server.py`.

## 4. Frontend Implementation (React)

### 4.1 New Pages
- **`src/pages/Login.jsx`**: A clean, modern login form prompting for email and password. On submit, calls `/api/auth/login`.
- **`src/pages/Signup.jsx`**: A registration form. On submit, calls `/api/auth/signup` and redirects to Login.

### 4.2 State Management
- Create an `AuthContext` in `src/contexts/AuthContext.jsx` to manage the user's logged-in state and provide `login()` and `logout()` functions to the rest of the application.

### 4.3 API Client Update (`src/services/api.js`)
- Update the fetch wrappers in `api.js` to automatically attach the `Authorization: Bearer <token>` header if a token exists in `localStorage`.
- If an API response returns a `401 Unauthorized` status, automatically clear the token and redirect the user to the Login page.

## 5. Execution Flow
1. Install necessary Python packages for JWT and password hashing.
2. Build the backend User models and JSON storage manager.
3. Implement the Auth router and JWT generation logic.
4. Update `server.py` to include the Auth router and protect existing routes.
5. Build the React `AuthContext`, `Login`, and `Signup` components.
6. Update `App.jsx` to conditionally render the Workspace only if the user is authenticated; otherwise, show the Login screen.
7. Update the frontend `api.js` to handle token injection.
